## 安装

需要 **Minecraft Java 26.3、Java 25、Fabric Loader 0.19.5 或更新版本，以及 Fabric API 0.161.0+26.3**。

当前构建为 `build/libs/big-fat-fish-1.3.1.jar`。将 JAR 与对应 Fabric API 放入游戏实例的 `mods` 文件夹。多人游戏中服务端和客户端均需安装。`-sources.jar` 是源码包，不用于游戏安装。

**1.2.1 修复安装 Sodium / Iris 时角色只剩影子的问题**：曲面通过原版自定义几何接口直接提交，不再修改零尺寸方块的面。已在 Sodium 0.9.2 + Iris 1.11.7（26.3 Fabric，无启用光影包）及原版渲染路径验证成年、幼年、两套皮肤和动画。升级时替换旧 JAR，角色和背包存档格式不变。

1.3.1 已用 Sodium 0.9.2 + Iris 1.11.7 完成当前像素模型的客户端验收（未启用光影包）。验证截图：[成年世界渲染](docs/screenshots/sodium-iris-adult.png) · [幼年世界渲染](docs/screenshots/sodium-iris-juvenile.png)。

GitHub 在线编译：进入仓库的 **Actions → Build Fabric Mod**，打开一次成功的运行，在页面底部 **Artifacts** 下载 `bigfatfish-mc26.3-...`，解压后取得可安装的 JAR。下载 artifact 需要登录 GitHub。每次推送 `main` 或提交 PR 都会自动编译并运行服务端 GameTest，也可以通过 **Run workflow** 手动编译。JAR artifact 保留 90 天，测试报告另存为 `gametest-report`。

## 大肥鱼

- 河流与冻河生物群系的河岸低概率自然生成，每次一只。也可在创造模式使用刷怪蛋，或使用 `/summon bigfatfish:big_fat_fish`。
- 未驯服时喜欢跟着手持米饭的玩家。每碗米饭独立进行一次 **1/3 概率**驯服判定，与 26.3 原版猫相同；失败也会吃掉米饭并返还碗，发出只对喂食者可见的对白。第一次可能成功，失败次数不增加后续概率。成功时先坐下等待命令。
- 生命上限 20（10 颗心），基础攻击伤害 1、攻击速度 4、移动速度属性 0.1、护甲 0；持剑通过原版装备属性获得相应伤害。
- **主人空手右键**：切换坐下/跟随。命令坐下时记录当前位置，之后的工作、战斗、偷懒和讨饭都受这个位置的 32 格半径限制。
- **主人潜行右键**：打开 27 格背包和 2 格装备栏；右手是主手，左手是副手。装备格直接与原版手持装备同步。
- **手持米饭右键**：喂食，优先于打开背包。恢复 8 点内部饥饿值和 4 点生命，生存模式返还碗；吃饭后 60 秒内不再消耗食物，幼年成功吃饭仍会加速成长。
- 跟随采用原版猫的距离阈值：超过 10 格开始追，进入 5 格内停下；停下后不会因为走到 6–9 格就再次贴近。距离达到 12 格且允许传送时使用原版宠物传送机制。主人离线时停留等待。
- 未被命令坐下时，附近有空床且主人在附近，偶尔会走到床上坐一会儿。主人走远会恢复跟随；命令坐下时使用固定工作位置。
- 只有主人可以下命令、喂食和打开背包。背包打开期间暂停活动，防止操作时跑走；离得太远会关闭。

## 工作、饥饿和对白

**体型与眼高：**按像素模型校准，成年碰撞箱宽 0.50、高 1.30 格，眼高 0.973 格；幼年宽 0.40、高 0.90 格，眼高 0.632 格。尾巴、鱼鳍耳及少量超出头顶的呆毛不扩大碰撞箱。

**幼年形态：**采用大头、短身体与短四肢的独立模型。自然生成和刷怪蛋全部产生幼年，指令可用 `/summon bigfatfish:big_fat_fish ~ ~ ~ {Age:-24000}`。使用原版年龄计时，正常约 20 分钟成年，每次成功喂米饭按原版喂食规则缩短剩余成长时间的约 10%；年龄和成长进度会保存。幼年只会跟随、休息、卖萌和要饭，拿剑或锄头都不会战斗或收割，也不显示手持工具；装备仍保存在背包页面。饱食期结束后，主人拿着米饭时会举手讨饭；成长后自动使用成年行为。

成年主手放入工具后，主人命令坐下即可工作：

| 主手 | 行为 |
| --- | --- |
| 锄头 | 收割工作位置半径 32 格、上下 4 格内成熟的原版 `CropBlock` 作物和本模组水稻；掉落直接收入背包 |
| 剑 | 主动寻找自身附近 16 格内可见敌对生物；跟随模式也会攻击，命令坐下时追击范围仍限制为 32 格 |
| 其他物品/空手 | 普通坐下或跟随；副手物品只负责持有，不触发工作 |

收割前先模拟背包是否容得下全部掉落，放不下就保留作物、停止收割并回座。清出足够空间后自动恢复。锄头和剑会消耗耐久；工具损坏后停止对应工作。收割产出先收入背包，再优先用背包中同种种子补种；缺少同种时选择其他能在该位置种下的种子。也会在工作范围内的空耕地种植。种植成功才扣除 1 个种子，没有种子就保留空地；水稻仍要求合法的一格深水源。

工作期间每 15 秒有 1/8 概率偷懒，闲逛 15–35 秒，仍在工作范围内；没有任务后回到原位置坐下。扫描只读取已加载区块，不强制加载远处农田。

内部饥饿值范围 0–20，每 20 秒可能减少 1：成年期间干过活的概率为 55%，休息为 12%，幼年为 45%。到 6 或以下会暂停工作；主人处于允许范围内时追着讨饭，喂饱后继续原先的命令。饥饿不会导致饿死，也不会自动偷吃背包里的物品。

预写中文傲娇对白覆盖驯服、吃饭、吃饱、坐下、跟随、讨饭、偷懒、收割、背包满、战斗、坐床、死亡，以及幼年的吃饭、撒娇和讨饭。未驯服时另有 6 句喂饭回应。发送为**只对主人可见的服务器聊天消息**，未驯服的回应只给喂食者；讨饭有 30 秒间隔，普通自动对白有 10 秒间隔。

背包、左右手、主人、坐下命令、工作位置和饥饿状态均会保存。死亡掉落背包和手持物品。

## 水稻与米饭

1. 在新生成河流区块的浅水河岸寻找水稻，成熟植株呈黄绿色。
2. 稻谷可直接种入**一格深的静水源**；底部支持泥土类、耕地、沙子和沙砾，水面上需预留两格空气。不能种在深水或流动水中。
3. 生长分 0–7 阶段，光照至少 9 时随机生长，也支持对底部使用骨粉。早期一格，中期两格，成熟三格：水下一格、水上两格。
4. 成熟时打掉任意一段，整株收获，共掉落 3 个稻谷；未成熟掉落 1 个。水源保留，可重新种植。生成仅在新区块发生，读档不会补回已收割的水稻。
5. 稻谷在石磨上加工为稻米，1:1。手持稻谷右键磨一个，潜行右键磨手中整组；产物放入玩家背包，放不下则掉落在玩家身边。
6. **3 个稻米 + 1 个碗**无序合成为 1 碗米饭。米饭与熟牛排相同，恢复 **8 点饥饿值、12.8 点饱和度**，吃完返还碗。

石磨有序合成（S = 石台阶，W = 木棍，C = 圆石）：

```text
S W S
C C C
C C C
```

使用镐拆除石磨。取得稻谷后解锁石磨配方，取得稻米后解锁米饭配方。

## 开发与验证

使用本机指定的 Microsoft JDK 25，脚本会先输出 `java -version` 和 `javac -version`：

```powershell
.\build.ps1                 # 编译并生成 JAR
.\build.ps1 test            # 独立服务器 GameTest
.\build.ps1 clienttest      # 实际客户端渲染、菜单同步与截图
.\build.ps1 run             # 开发客户端
python tools/check_pixel_import.py        # 像素模型导入、硬边法线、骨骼和贴图检查
```

构建工具为 Gradle 9.6.0、Fabric Loom 1.17.21。已缓存依赖时可直接使用 `gradlew.bat ... --offline`。首次客户端启动会下载 Mojang 官方资源。

服务端测试报告位于 `build/gametest-results.xml`；客户端测试截图位于 `build/clienttest/screenshots/`。29 项模组服务端测试覆盖水稻、工作范围、权限、装备与存档、饥饿、幼年尺寸及成长、纯幼年自然生成、好感度与饱食拒食、长期未喂衰减、负好感跑路与物品掉落、−100 后立即喂饭不能取消跑路且不会重复掉落、繁育条件与冷却、命名牌以及对白阶段。另有 1 项 Fabric 基础测试。客户端测试检查四套外观、年龄同步、真实换肤和繁育按钮、拒绝发言、跑路消息和实体移除、冷却及名字同步、动作、角色画面像素与完整三视图；世界关闭后自动删除。

角色采用块状低模与 128×128 像素贴图，以 Blockbench 中维护的 [成年完整模型](models/bigfatfish_pixel.bbmodel) 和 [幼年完整模型](models/bigfatfish_pixel_juvenile.bbmodel) 为权威源。两个项目均包含女仆装、夏装和动画骨骼。先在编辑器完成几何、UV、骨骼和外观检查，保存正常站姿，再导回运行时压缩网格；`--pixel` 保留硬边和编辑器 UV，不套用旧曲面模型的平滑处理：

```powershell
python tools/import_blockbench.py models/bigfatfish_pixel.bbmodel --pixel --check
python tools/import_blockbench.py models/bigfatfish_pixel_juvenile.bbmodel --pixel --juvenile --check
python tools/import_blockbench.py models/bigfatfish_pixel.bbmodel --pixel
python tools/import_blockbench.py models/bigfatfish_pixel_juvenile.bbmodel --pixel --juvenile
```

`--full` 是默认行为。根节点原点必须保持 `[0,24,0]`；导回要求将非零组/网格旋转或缩放应用到顶点，不要保存临时动作预览为模型源。通过本地 Blockbench MCP 打开完整项目后，可运行 `python tools/blockbench_pose.py sitting` 或 `python tools/blockbench_pose.py clasp` 临时预览坐姿和抱手动作。脚本在 `build/` 保存截图，并在结束时恢复网格、骨骼原点和旋转；这是姿态变形预览，不包含物理碰撞或游戏 AI。全部编辑完成后再进行最终客户端验收。

`tools/generate_character.py` 保留程序化初始模型和几何检查函数；只要完整 BB 源存在，直接运行就会拒绝覆盖运行时资源。`python tools/generate_character.py --procedural` 会明确用程序化几何替换资源，不能用于保存 Blockbench 编辑成果。

`CharacterMesh.java` 使用原版 `submitCustomGeometry` 接口提交网格，`FishModel.java` 控制骨骼和动作，无第三方模型运行库。头发与尾巴会随移动、转向产生弹簧缓动；关节使用连续弯曲，鞋子保持刚性。客户端测试额外检查四套外观截图中的实际角色像素，防止模型消失但实体同步仍正常时误报成功。可将 Sodium 和 Iris 的对应版本 JAR 放入隔离测试目录 `build/clienttest/mods` 后运行客户端测试。其余物品和作物资源、对白通过 `python tools/generate_assets.py` 生成。

Blockbench 项目内嵌材质图集和睁眼脸部贴图；导回网格不会自动覆盖 PNG。修改贴图时，将图集导出到 `character_atlas.png`，脸部导出到 `adult_face.png` 与 `face.png`，并同步相同 UV 布局的两个 `_closed.png`。五张角色贴图均关闭模糊过滤，保留清楚的像素边缘。当前像素贴图在 Blockbench 中绘制，构建不会重新生成它们。
